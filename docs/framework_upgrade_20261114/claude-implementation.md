## Changes

- `integrations/claude/python/src/sparseread_claude/hook.py` and new `hook_state.py`: installed `--single` process uses a locked, bounded, 24-hour state keyed by workspace/session/path and source stat identity. Missing identity, corrupt/unavailable state, lock contention, unsafe state symlinks and oversize state fail open without overriding Claude permissions. Hook policy is neutral unless explicitly denying; advisory only supplies context. Structured deny exits zero so the host processes JSON. Auto targets unbounded Read and plain single-file `cat` only; bounded reads, grep/head/tail, pipes and unknown commands remain native. Directories are not inspected by this pre-permission hook. Official `tool_response` is used, and PostToolUse suggestions use `additionalContext` without replacing the tool output. Boundary-whitespace paths are not redirected.
- `claude_mcp.py`: eight-tool MCP server marks protocol/data errors as `isError`, documents Unicode character/exclusive-end raw ranges, anchors paths within the configured workspace, rejects external symlinks, and binds preview/read/raw/card/decide to the core source manifest. The preflight is explicitly limited to top-level regular files and uses bound individual-file decisions; other permitted paths are available through explicit preview. A Claude host's MCP tool authorization covers the tool invocation; it is **not** a native Read per-file approval. A collection call may read multiple authorized-target files. Core manifest checks are not an atomic filesystem sandbox against malicious concurrent mutation.
- `scripts/install_sparseread.py`: public auto/advisory flows to both MCP and hooks. Reinstall replaces only this adapter's entries while preserving other hooks, creates the managed runtime at its final path, and rolls runtime/config/guidance back if later install or doctor fails; prior configuration permissions are preserved. Existing `CLAUDE.md` is retained, so its existing content must be reviewed when changing modes. Codex doctor now labels transport/config separately from host activation and prints the independent diagnostic command; it never grants trust or runs that fixture automatically.
- `integrations/claude/CLAUDE.md`, `integrations/claude/README.md`, `integrations/claude/python/README.md`, and the Claude paragraph of `docs/installation.md` describe mode, permissions, workspace, native fallback and platform boundaries. Existing user guidance is not overwritten on reinstall.
- Tests added: `integrations/claude/python/tests/test_claude_hook_subprocess.py`, `test_claude_mcp_stdio.py`; existing `test_claude_hook.py` and `tests/test_install_sparseread.py` updated or extended. Native-permission and unchanged-output assertions replace the old `allow`/`updatedToolOutput` expectations.
