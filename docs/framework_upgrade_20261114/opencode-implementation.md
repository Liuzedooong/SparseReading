# OpenCode V2 implementation and verification (2026-11-14)

Baseline: public commit `d30f75f83c3976f693d5ee9c10c3569ca89d9b40`; changes are in the shared integration checkout, not the research workspace. The integration targets the official `@opencode/cli@2.3.0` and `@opencode/plugin@2.3.0` packages. The legacy function entry remains separate from the V2 `Plugin.define` entry; both use the same JSONL transport. No release was published and version metadata has not been bumped.

V2 registers five direct-only tools, forwards session/message/call IDs, derives the workspace from the actual session, and refuses an unknown or remote workspace. Its normal native-tool handoff keeps the same tool and checks the original source before rewriting. Bounded reads are left to the host. Tool output has an explicit schema; completed native results retain attachments and structured output, and errors are not turned into successes. Native traces are session-local. Execution success and deletion use `event.data`; failures and interruptions are recorded without marking a successful final answer.

The adapter authorizes direct paths before manifest discovery, then authorizes the manifest root and each lexical/canonical source path with the host's `read` and, for external paths, `external_directory` permissions. The bridge verifies the one-use manifest token against session and source before reading. Its check-to-open window is not an atomic filesystem sandbox. Collection manifests are enabled after independent source review. Real-host fixtures passed allowed preview/focus/raw, denied child, symlink rejection, native directory fallback, and rejection of an old raw reference after a same-size child rewrite; unsupported/unreadable/oversized sources fall back to native. Remaining concurrency and packaged-release tests are in progress. A rejected permission is not converted into a successful SRO result.

Reminder files use unique random names, exclusive no-follow creation, checked workspace-owned directory components, and deletion after tool completion or unload; a reminder is authorized before rewriting. V2 bridge children receive a limited environment, reject malformed frames, recover after crash or timeout, and are stopped on cleanup. Their lifecycle is per session. The shell handoff detects only the documented simple commands and does not claim to intercept arbitrary program I/O.

Installer detects host major, manages either V1 or V2 entry, refuses unmanaged collisions, and builds the Python core/adapter wheels into the managed runtime. The V2 package contains the exact SDK module needed by its entry. Doctor creates a temporary workspace and uses an isolated real OpenCode host plus a deterministic local provider to check all five tool registrations and a completed synthetic preview; it is a host integration check, not evidence of a real model or performance. Source archive allowlist includes V2, transport, npm settings and doctor; final archive testing requires the integrator's commit.
